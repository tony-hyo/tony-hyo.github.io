# Animated Wedding Invitation — Design

Date: 2026-09-02
Status: approved in conversation, ready for planning

## Goal

A single-page, static, mobile-first wedding invitation. A guest opens a
personalized link, taps a sealed envelope, watches the card slide out, and
scrolls to three buttons: RSVP on Withjoy, add to calendar, get directions.
No backend, no database, no tracking.

## Decisions already made

| Topic | Decision |
|---|---|
| Opening flow | Envelope: tap, flap opens, card rises out, card settles at full size |
| Below the card | Buttons only, for now. More sections may be added later |
| Theme | Cherry blossom on warm off-white paper, dark brown ink, wide-tracked serif capitals, script accents, branch anchored top-right |
| Artwork | Hand-authored SVG branch now, swappable for a purchased illustration later |
| Personalization | Guest name from the `?to=` query parameter |
| Music | None |
| Stack | Plain HTML, CSS, and JS. No build step, no dependencies |
| Animation | CSS transitions and keyframes driven by class toggles. Web Animations API or GSAP only if this proves limiting |
| Hosting | Cloudflare Pages, free tier. Netlify is the fallback. Custom domain later |
| Local preview | Must work by opening `site/index.html` directly from disk (`file://`) |
| Email sending | Out of scope. A separate program will send each guest their link |

## Browser script strategy

Chrome refuses ES module imports on `file://` pages, and local double-click
preview is a requirement. So browser scripts are classic `<script>` tags, and
the two files Node also needs (`config.js`, `invite-logic.js`) use a small
wrapper that assigns to `window` in the browser and to `module.exports` in
Node:

```js
(function (root, factory) {
  var api = factory();
  if (typeof module === 'object' && module.exports) module.exports = api;
  else root.InviteLogic = api;
})(this, function () { /* ... */ });
```

`package.json` has no `"type": "module"`, so Node treats these as CommonJS.

## Configuration

`site/js/config.js` exports one object:

```js
{
  coupleNames: 'Tony & Jamie',
  eventTitle: "Tony & Jamie's Wedding",
  start: '2027-06-12T16:00:00-07:00',                // ISO 8601 with offset
  end:   '2027-06-12T23:00:00-07:00',
  timeZone: 'America/Los_Angeles',                   // IANA name, for Google Calendar display
  venueName: 'The Garden Pavilion',
  venueAddress: '123 Blossom Lane, Sacramento, CA 95814',
  mapUrl: '',                                        // optional override; empty = build from address
  rsvpUrl: 'https://withjoy.com/tony-and-jamie',
  siteUrl: 'https://tony-and-jamie.pages.dev',       // absolute, for calendar description and UID
  calendarDescription: 'Details and RSVP: https://withjoy.com/tony-and-jamie'
}
```

Human-facing text (names on the card, the written date, venue lines,
"Reception to follow") is edited directly in `index.html`. The date therefore
appears in two places, `config.js` and `index.html`. README calls this out.

## Visual design

Palette (CSS custom properties on `:root`):

| Token | Value | Use |
|---|---|---|
| `--paper` | `#F7F3EE` | page background |
| `--card` | `#FCFAF6` | card face |
| `--ink` | `#3B2A26` | text |
| `--ink-soft` | `#7A6660` | secondary text, hints |
| `--blush` | `#F5E4E8` | envelope outer |
| `--blush-deep` | `#EBCBD4` | envelope shading |
| `--liner` | `#E9A9BE` | inside of the flap |
| `--blossom` | `#E99BB4` | petals, mid pink |
| `--blossom-light` | `#F4C6D3` | petals, light pink |
| `--blossom-deep` | `#D6608A` | primary button, seal, blossom centers |
| `--branch` | `#4A3228` | branch strokes |

Type:

- `--font-serif`: Cormorant Garamond, weights 300, 400, 500, italic 400.
- `--font-script`: Mrs Saint Delafield, fallback `cursive`.
- Headline: uppercase, letter-spacing `0.28em`, weight 400.
- Names: serif 400, sentence case, large.
- Big date: serif 300, letter-spacing `0.2em`.
- Small lines: uppercase, letter-spacing `0.18em`, size ~0.75rem.
- The guest name line is serif italic, not script, so names stay legible.
  Script is reserved for decorative phrases.

Fonts load once from Google Fonts with `display=swap`.

Layout:

- Card width `min(92vw, 440px)`, padding `2.5rem 2rem`, radius 2px, soft
  shadow, subtle paper gradient. Text left-aligned like the reference.
- Branch is absolutely positioned top-right, about 62% of card width,
  overflow clipped by the card.
- Details section shares the card column width and is centered.
- Envelope width `min(88vw, 400px)`, aspect ratio 1.45.
- Desktop shows the same portrait card centered on the paper background.

## Opening sequence

All timings are CSS transitions or keyframes on `body.is-open`. JS only
toggles classes and, at the end, unlocks scroll and moves focus.

| From | Duration | What |
|---|---|---|
| 0.0s | 0.7s | Flap rotates on the X axis from 0 to 180 degrees. At 50% its z-index drops below the card and its color swaps from blush to liner pink, which is invisible because the flap is edge-on at that instant. The seal fades out. |
| 0.5s | 0.8s | Mini card translates up about 70% of its height, ease-out. |
| 1.2s | 0.5s | Envelope group fades to 0 and drifts down 24px. Tap hint fades. |
| 1.2s | 0.7s | Real card fades in and scales from 0.94 to 1. |
| ~1.9s | | JS: `body.is-closed` removed, scroll unlocked, petals layer gets `is-falling`, focus moves to the card headline. |
| 2.4s | 0.6s | Scroll chevron fades in and bobs gently. |

Before opening, `body.is-closed` sets `overflow: hidden` and the real card
is `opacity: 0` and `pointer-events: none`. The envelope is a real `<button>`
so Enter and Space also open it.

`prefers-reduced-motion: reduce`: every duration becomes 0, petals never
animate, the opening is an instant state change.

## Petals

- A fixed, full-viewport layer with `pointer-events: none`, above content.
- JS creates 14 petal elements, each an inline `<svg><use href="#petal"></svg>`.
- Each petal gets inline custom properties: `--x` (0 to 100vw), `--size`
  (10 to 18px), `--fall` (9 to 16s), `--delay` (0 to 12s), `--sway` (20 to
  60px), `--spin` (rotation degrees).
- Two keyframe animations: `petal-fall` on the wrapper (top -10vh to 110vh,
  linear, infinite) and `petal-sway` on the inner svg (translateX between
  `-var(--sway)` and `var(--sway)` with rotation, ease-in-out, alternate).
- Opacity 0.85, colors alternate between `--blossom-light` and `--blossom`.
- Animations only run when the layer has `is-falling`.

## Blossom branch artwork

`assets/blossom-branch.svg`, viewBox `0 0 400 300`, transparent background.
A main branch entering from the right edge with two or three sub-branches
in `--branch`, tapered stroke widths. Around 25 blossoms, each a group of
five rounded petals in `--blossom-light` or `--blossom` with a small
`--blossom-deep` center, at varied sizes and rotations, plus a few buds and
loose petals. Kept under 20KB. Referenced by `<img>` so swapping it for a
purchased PNG or SVG is a one-line `src` change.

## Logic module (`invite-logic.js`)

All functions are pure and take their inputs explicitly so tests need no
DOM, clock, or globals.

- `getGuestName(search, fallback)` → string. Reads `to` from a query string,
  decodes, trims, collapses internal whitespace, strips control characters,
  caps at 60 characters. Returns `fallback` for missing, empty, or
  whitespace-only values. Inserted into the DOM with `textContent`.
- `countdown(now, start, end)` → `{ state, days, hours, minutes }` where
  `state` is `'before'`, `'today'`, or `'after'`. `'today'` covers start
  through end. Whole units, floor, never negative.
- `toIcsUtc(date)` → `YYYYMMDDTHHMMSSZ`.
- `googleCalendarUrl(config)` → `https://calendar.google.com/calendar/render?action=TEMPLATE&text=...&dates=...Z/...Z&details=...&location=...&ctz=...`.
- `mapsUrl(config)` → `config.mapUrl` if set, else
  `https://www.google.com/maps/search/?api=1&query=<encoded name + address>`.
- `buildIcs(config, now)` → string. VCALENDAR 2.0, PRODID, METHOD:PUBLISH,
  one VEVENT with UID (`wedding@<siteUrl host>`), DTSTAMP, DTSTART/DTEND in
  UTC, SUMMARY, DESCRIPTION, LOCATION, URL. Text fields escaped for
  backslash, semicolon, comma, and newline. Lines folded at 75 octets. CRLF
  line endings.

`scripts/make-ics.js` requires config and `buildIcs`, writes
`site/wedding.ics`. A static file is used instead of a client-side Blob
because iOS Safari handles a real `.ics` URL far more reliably.

## Main script (`main.js`)

1. Read `INVITE_CONFIG` and `InviteLogic` from `window`.
2. Fill guest name into every `[data-guest]` (envelope address and card).
3. Set `href` on `[data-rsvp]`, `[data-directions]`, `[data-gcal]`.
4. Start the countdown: render now, then every 60s aligned to the next
   minute boundary, and again on `visibilitychange` when the tab returns.
5. Build the petals layer.
6. Wire the envelope: on `click`, add `body.is-open`. After the sequence
   (listen for `transitionend` on the real card, with a 2.5s `setTimeout`
   fallback), remove `is-closed`, add `is-falling` to petals, focus the
   headline. Ignore repeat clicks.
7. IntersectionObserver on `.details`: add `is-visible` at 15% visibility,
   once.
8. If reduced motion is preferred, skip petals and let CSS handle the rest.

## Link previews

`<head>` carries `og:title`, `og:description`, `og:image`, `og:url`,
`twitter:card=summary_large_image`. `og:image` must be an absolute URL, so
it points at `<siteUrl>/assets/preview.png` and README reminds the owner to
update it after the first deploy. `preview.png` is rendered from
`scripts/preview.html` with headless Chrome at 1200x630.

## Accessibility

- Envelope is a `<button>` with an accessible name.
- Focus moves to the headline after opening.
- Petals layer and branch image are `aria-hidden` / empty `alt`.
- Contrast: ink on paper exceeds 10:1. Primary button white on
  `--blossom-deep` is about 4.6:1, meets AA for the button's text size.
- The countdown is plain text, not a live region. It updates every minute
  and a live region would chatter.

## Deployment

Cloudflare Pages, Git-connected:

1. Push the repo to GitHub (any account; the repo may be private).
2. Cloudflare dashboard → Workers & Pages → Create → Pages → Connect to Git.
3. Build command: empty. Build output directory: `site`.
4. Project name becomes the `*.pages.dev` subdomain.
5. Update `siteUrl` in `config.js` and the `og:*` URLs in `index.html` to
   the real address, regenerate `wedding.ics`, push again.

Direct upload alternative: drag the `site` folder onto the Pages dashboard.
Custom domain: Pages → Custom domains → add, then follow the DNS prompt.

## Testing

- `npm test` runs `node --test test/`. Covers: guest name parsing (missing,
  empty, encoded ampersand, plus signs, whitespace, control characters,
  length cap), countdown (before, at start, during, at end, after, floor
  behavior), Google Calendar URL (encoding, UTC dates, timezone param),
  maps URL (override vs generated), ICS (structure, escaping, folding,
  CRLF, UTC stamps).
- Manual: open `site/index.html` in Chrome at 390x844 and 360x800 viewports
  and on desktop. Verify closed state, the opening sequence, petals, scroll
  reveal, all three links, reduced-motion behavior, and the `?to=` name.
- Screenshots of the closed and open states are captured during the build
  for review.

## Out of scope

- Music, RSVP capture, guest list, analytics.
- Additional sections (schedule, photos, dress code). Add later as new
  `<section>` blocks in the details area.
- Email sending program.
- Seamless single-element card handoff. The current design crossfades a
  mini card into the real card. If it ever looks wrong, a FLIP transition
  on one shared element is the upgrade path.
